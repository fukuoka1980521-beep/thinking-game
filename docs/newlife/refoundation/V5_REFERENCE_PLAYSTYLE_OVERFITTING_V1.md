# NEW LIFE V5 — REFERENCE PLAYSTYLE VS OVERFITTING

Date: 2026-09-24
Status: DESIGN PRINCIPLE / NO PRODUCT CODE

## Purpose

Repeated testing with one tester can accidentally tune a game to that tester's response style.

That can be avoided without discarding useful design discoveries from the test.

## Reference path observed in V3

The successful V3 path used several reusable moves:

- ask for the missing reason before judging;
- separate the immediate practical problem from the later personal concern;
- prefer a reversible compromise;
- normalize a concern without dismissing it;
- use perspective reversal ("if a friend brought this to you?");
- break a vague concern into a specific boundary;
- pair a boundary with an acceptable alternative;
- turn the result into a small next action.

These moves may become part of NEW LIFE's distinctive thinking philosophy.

They must not become a required writing style.

## Product rule

NEW LIFE should evaluate the function of an action, not whether the player uses long, polished, empathetic language.

For example, these may represent the same underlying move:

Long:
> 「本人に直接言いにくければ、信頼できる人に一度相談してみたらどうだろう」

Short:
> 「まず誰か一人に相談したら？」

Both can be valid.

## Multiple viable play styles

Cases should support several approaches with different trade-offs:

### Facilitative
Keeps people talking and seeks workable compromise.

### Direct
Makes decisions quickly and surfaces conflict early.

### Evidence-seeking
Separates facts from assumptions and tests uncertainty.

### Delay / space-making
Avoids premature decisions and gives parties time.

### Low-verbal
Uses short practical statements rather than long explanations.

No style is globally correct.

A case is overfit if only one of these can reach a robust outcome.

## Differentiation

There is a valid product strategy in having a recognizable NEW LIFE way of organizing difficult situations.

The distinction is:

- GOOD differentiation: a recognizable thinking framework that different player styles can use.
- BAD overfitting: rewarding one tester's exact tone, wording, or preferred conversational manner.

## Validation gate

Each major case must be checked against:
- facilitative player;
- direct player;
- skeptical/evidence-seeking player;
- delaying player;
- short-response player.

Do not decide yet whether the final product should be broad or strongly opinionated.

Use:
- owner human testing;
- blind AI review;
- later non-owner human testing

to make that decision deliberately.
